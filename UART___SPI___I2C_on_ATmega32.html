Communication Protocols

UART, SPI and I2C

01 · INTRODUCTION

What is a communication protocol?

Large projects rarely run on one chip. A sensor, a display, an SD card and a second MCU all need to exchange bytes with the main controller — reliably, over as few wires as possible.
A communication protocol is simply the agreed set of rules for doing that: which wires exist, how a bit is represented, when it is valid, and how a message starts and ends.

SERIAL vs PARALLEL
Parallel sends every bit of a byte at once, one wire per bit. Serial sends them one after another on a single wire — fewer pins, works over longer distances, used by all three protocols here.
SYNCHRONOUS
SPI and I2C share a clock line between devices, so bits are sampled exactly when the clock says to.
ASYNCHRONOUS
UART has no clock wire at all — both sides are pre-configured to the same baud rate and trust that timing.
01 · INTRODUCTION

Direction of data & who is in charge

Two more questions describe every link: can data flow both ways (and at the same time?), and is there a boss on the bus?

SIMPLEX vs HALF vs FULL DUPLEX

Simplex — data only ever flows one way. Half duplex — both can send, but they take turns on the same line. Full duplex — a separate path each way, so both send simultaneously.

MASTER–SLAVE vs PEER-TO-PEER

Master–slave — one device (the master) generates the clock and decides who talks and when; slaves only answer (SPI, I2C). Peer-to-peer — both devices are equal and may start sending whenever they like (UART).

02 · UART — OVERVIEW

Universal Asynchronous Receiver/Transmitter

ASYNCHRONOUSFULL DUPLEXPEER-TO-PEER2 WIRES: TX · RX

TX → RX, BOTH WAYS AT ONCE

Idea
The transmitter turns a parallel byte into a serial frame; the receiver rebuilds the byte from that frame.
Wiring
Cross the lines — TX of one goes to RX of the other — and always connect a common GND.
02 · UART — DATA FRAME

How a byte is packed on the wire

EXAMPLE — SENDING 'A' (0x41), 8E1

Start bit
Always 0 — pulls the idle-high line low, telling the receiver a frame begins.
Data bits
5 – 9 bits, LSB first. 8 is standard on the ATmega32.
Parity*
Optional error-check bit: ODD sets it so the total 1-bits is odd, EVEN so it's even. Often disabled (8N1).
Stop bits
1 or 2 bits, always 1 — returns the line high and marks the end of the frame.
Baud rate
Bits per second; both ends must match. Common values: 1200 – 115200 bps (we use 9600).
02 · UART — HOW DATA IS RECEIVED

Finding the bits without a clock

The receiver runs its own clock at 16× the baud rate and uses the start bit's falling edge as its reference point.

  1. Idle — the line sits HIGH; the receiver keeps watching it.
  2. Falling edge — HIGH → LOW means a start bit may have begun.
  3. Validate — wait ½ bit (8 ticks) and check the line is still LOW; if not, it was noise and is ignored.
  4. Sample data — every 1 bit time (16 ticks) from there, read the line in the middle of each bit, D0 → D7 (the ATmega32 takes 3 samples there and majority-votes).
  5. Check stop — the stop bit must read 1, otherwise a Framing Error (FE flag in UCSRA) is raised.
  6. Done — the byte is moved into UDR and the RXC flag is set for your code to read.
02 · UART — BAUD MISMATCH

Sampling too quick & too slow

Same frame on the wire ('A' = 0x41, 8N1), three receivers. Because the receiver only re-synchronises on the start bit, any timing error adds up bit after bit.

Too quick
Receiver baud higher than sender's → samples come early and drift left. Bits get read twice, the last bits are never reached, and the "stop bit" sample can land on a data bit (framing error if that bit is 0).
Too slow
Receiver baud lower than sender's → samples come late and drift right. Bits get skipped, and later samples read the stop bit or idle line as data.

02 · UART — PROS & CONS

When UART is the right choice

ADVANTAGES

  • Only 2 wires (TX, RX) + ground
  • No clock signal needed between devices
  • Full duplex — send and receive at the same time
  • Parity bit allows basic error checking
  • Frame format & baud are configurable as long as both sides match
  • Simple and everywhere — every MCU, PC (USB-TTL), GPS, Bluetooth module

DISADVANTAGES

  • Data frame limited to max 9 bits
  • Only 2 devices — no multi-device bus, no addressing
  • Baud rates must match within a few % or data is garbled
  • Slower than SPI (typically ≤ 115.2 kbps)
  • Overhead — start/stop bits waste 20% of the bandwidth
  • No acknowledgement — the sender never knows the byte arrived

MISO
Master Input / Slave Output — slave → master data line, same clock edge.
SCLK
Clock, always generated by the master — this is what makes it synchronous.
SS/CS

HOW IT WORKS — TWO SHIFT REGISTERS IN A RING

03 · SPI — HOW DATA IS SENT

One transfer, step by step

STEP 1 · CLOCK

The master is the only device allowed to drive SCLK. Before any device is selected, the master can already be toggling the clock — nothing is read or written until a slave is selected.

STEP 2 · SELECT

The master pulls that slave's SS/CS pin LOW (active-low). Only the selected slave will drive MISO or read MOSI; every other slave on the bus ignores the clock.

STEP 3 · MASTER → SLAVE (MOSI, MSB FIRST)

On each clock edge the master shifts one bit out on MOSI. This example sends 11000010 MSB first — the bit order is set by the DORD bit in SPCR.

STEP 4 · SLAVE → MASTER (MISO, LSB FIRST)

Full duplex means the slave can shift a byte back on MISO at the same time the master is sending on MOSI. Here the slave happens to send 11000010 LSB first — bit order is set per device, both sides just need to agree.

03 · SPI — MULTIPLE SLAVES

One master, many slaves

A · INDEPENDENT SLAVE SELECT

  • One SS pin per slave — master pulls only one LOW at a time
  • Unselected slaves release MISO so they don't clash
  • Talk to any slave directly, at full speed
  • Needs an extra master pin for every slave

B · DAISY CHAIN

  • A single SS line for all slaves
  • Each slave's MISO feeds the next slave's MOSI; the last one returns to the master
  • Data ripples through: for 3 slaves, clock out 3 bytes
  • Slower to reach one device, and one dead slave breaks the chain

03 · SPI — PROS & CONS

When SPI wins

ADVANTAGES

  • No start/stop bits — data streams continuously without interruption
  • No addressing scheme to manage — SS picks the slave
  • Fastest of the three — ~2× I2C, several MHz (up to F_CPU/2 on the ATmega32)
  • Full duplex — separate MISO/MOSI lines
  • No baud rate to agree on — the master's clock times everything

DISADVANTAGES

  • 4 wires vs I2C's 2 — plus one more SS per extra slave
  • No acknowledgement that data was received
  • No error checking like UART's parity bit
  • Single master only
  • Short distance — meant for on-board links
04 · I2C — OVERVIEW

Inter-Integrated Circuit

SYNCHRONOUSHALF DUPLEXMASTER–SLAVE2 WIRES: SDA · SCL
SDA / SCL
Serial Data and Serial Clock — both idle high via pull-up resistors, pulled low to signal.
Addressing
7-bit slave address + 1 R/W bit sent as the first byte after START — no separate SS wire needed.
ACK/NACK
Receiver pulls SDA low after every byte to acknowledge; no pull-down means NACK (busy, error, or "stop sending").

ONE BUS, MANY ADDRESSED DEVICES

04 · I2C — MESSAGE & STEPS

How an I2C message is built

Data is sent in messages, broken into 8-bit frames. Every frame is followed by an ACK bit from the receiver.

  1. START — the master pulls SDA low while SCL is still high; every slave starts listening.
  2. Address frame — the master sends the 7-bit slave address (A6 … A0) followed by the R/W bit (0 = write, 1 = read).
  3. ACK — every slave compares the address with its own; only the matching one pulls SDA low for one clock.
  4. Register / data frames — 8 bits each, MSB first (here: which internal register, then the data). Sent by the master to write, by the slave to read.
  5. ACK after every frame — the receiver confirms each byte; a NACK tells the sender to stop.
  6. STOP — the master releases SDA to high while SCL is high; the bus is free again.
04 · I2C — START & STOP CONDITIONS

What the wires actually do

Normally SDA is only allowed to change while SCL is low. START and STOP are the two exceptions — that is how every device on the bus can recognise them.

START

SDA goes HIGH → LOW while SCL is HIGH. The bus is now busy.

DATA & ACK

One bit per SCL pulse, set while SCL is low and read while it is high. On the 9th pulse the receiver holds SDA LOW = ACK.

STOP

SDA goes LOW → HIGH while SCL is HIGH. The bus is free. (A START without a STOP first = repeated START.)

04 · I2C — PROS & CONS

When I2C is the right choice

ADVANTAGES

  • Only 2 wires, however many devices are on the bus
  • Many slaves (up to 112 with 7-bit addresses) and multiple masters
  • ACK/NACK confirms every byte was received
  • Built-in addressing — no extra select pins
  • Hardware is simple — just two pull-up resistors; widely used (RTC, IMU, EEPROM, LCD backpacks)

DISADVANTAGES

  • Slower than SPI — 100 kHz standard, 400 kHz fast mode
  • Half duplex — one direction at a time
  • Protocol overhead — START, address, ACK bits, STOP
  • More complex hardware/software than SPI
  • Address clashes — two identical chips may share an address
  • Short distance — bus capacitance limits it to on-board links
